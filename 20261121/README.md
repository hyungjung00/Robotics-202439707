## 2. 이론적 배경

### 2.1 IMU (Inertial Measurement Unit, 관성 측정 장치)
로봇의 **회전과 움직임**을 측정하는 센서 묶음이다. 바퀴 엔코더만으로는 미끄러짐이나 회전을 정확히 알기 어렵기 때문에, IMU를 함께 써서 로봇의 자세와 방향을 추정한다.

| 센서 | 측정값 | 단위 | 장점 | 단점 |
|---|---|---|---|---|
| **Gyroscope (자이로)** | 각속도 (얼마나 빨리 회전하는지) | rad/s, °/s | 빠른 회전에 정확, 진동에 강함 | 적분해서 각도를 구하면 오차가 계속 쌓임 (**Drift**) |
| **Accelerometer (가속도계)** | 선가속도 (**중력 포함**) | m/s², g | 중력 방향을 알 수 있어 기울기(roll/pitch) 계산 가능, 장기적으로 안정 | 진동·충격에 민감 (노이즈 큼) |
| **Magnetometer (지자기 센서)** | 지구 자기장 방향 (나침반) | µT | 절대 방향(yaw, heading)을 알 수 있음 | 모터·금속·전선 주변에서 자기장 왜곡 |

- 축 개수에 따라 6축 IMU(자이로 3축 + 가속도 3축), 9축 IMU(+ 지자기 3축)로 부른다.
- 각 센서의 단점을 서로 보완하기 위해 **센서 퓨전(Sensor Fusion)** 을 한다.
  - **상보 필터(Complementary Filter)** : 짧은 시간에는 자이로를, 긴 시간에는 가속도계를 믿도록 가중 평균한다.
    ```
    angle = α × (angle + gyro × dt) + (1 − α) × accel_angle      (α ≈ 0.98)
    ```
  - **칼만 필터(Kalman Filter)**, **Madgwick / Mahony 필터** : 더 정교한 확률 기반·쿼터니언 기반 퓨전 알고리즘. ROS2에서는 `imu_filter_madgwick` 같은 패키지로 사용할 수 있다.

### 2.2 중력가속도와 z축 값 (센서 테스트 해석)
- 가속도계는 **정지해 있어도 중력 때문에 약 9.8 m/s²(1g)** 를 측정한다. 실제로는 중력 자체가 아니라 바닥이 센서를 위로 떠받치는 힘(반작용)을 측정하는 것이다.
- 그래서 로봇을 평평한 곳에 두면 x, y축은 0에 가깝고 **z축에만 약 ±9.8** 이 나온다.
- 부호(+/−)는 센서 칩이 놓인 방향과 드라이버의 축 정의에 따라 달라진다. 이번 실습에서는 **z축 −9.8** 이 측정되었다.
  - 참고: ROS의 IMU 규약(REP-145)은 평평하게 정지한 상태에서 z축이 **+9.81** 이 되도록 정의한다. 값을 ROS2 패키지(위치 추정, SLAM 등)에 넣을 때는 이 부호와 축 방향을 맞춰야 한다.
- 정지 상태의 가속도 값으로 기울기를 계산할 수 있다.
  ```
  roll  = atan2(ay, az)
  pitch = atan2(−ax, √(ay² + az²))
  ```
- 정지 상태인데 자이로 값이 0이 아니면 그 값이 **바이어스(offset)** 이다. 처음 몇 초간 평균을 내서 빼 주는 보정(캘리브레이션)을 한다.

### 2.3 통신 프로토콜이란 (Communication Protocol)
MCU와 센서, 액추에이터, 외부 제어 장치(SBC 등) 사이에서 데이터를 주고받기 위한 **통신 규칙**이다.

| 프로토콜이 정하는 것 | 예시 |
|---|---|
| 데이터 전송 순서 | LSB부터 보낼지, MSB부터 보낼지 |
| 신호 타이밍 | 1비트를 몇 µs 동안 유지할지 (baud rate, 클럭) |
| 전송 형식 | Start bit / Data / Parity / Stop bit 같은 패킷 구조 |
| 장치 식별 방법 | I2C 주소, SPI의 CS 핀, CAN의 메시지 ID |

임베디드 시스템에서는 선 개수가 적고 배선이 단순한 **직렬 통신**을 주로 사용한다.

### 2.4 동기 방식 vs 비동기 방식

| 구분 | 동기 (Synchronous) | 비동기 (Asynchronous) |
|---|---|---|
| 타이밍 맞추는 법 | **클럭선**을 따로 두고, 클럭 신호(타이머로 만든 일정한 주기)에 맞춰 비트를 읽음 | 클럭선 없이 양쪽이 **미리 약속한 속도(baud rate)** 로 각자 타이밍을 계산 |
| 필요한 선 | 데이터 + 클럭 | 데이터만 |
| 속도 | 빠르게 올리기 쉬움 | 양쪽 클럭 오차가 쌓이면 오류 → 속도에 한계 |
| 대표 예 | I2C, SPI | UART |

### 2.5 UART (Universal Asynchronous Receiver/Transmitter)
- **비동기** 방식으로, 양쪽이 **같은 baud rate** 를 약속하고 통신한다 (이번 실습: **115200 bit/s**).
- 연결: **TX → RX, RX → TX** 로 교차 연결 (+ GND 공통).
- 1 : 1 통신이고 전이중(동시에 송수신 가능)이다.
- 활용: SBC ↔ MCU 통신, **LiDAR**, GPS, 디버깅용 시리얼 모니터

**UART 프레임 구조 (8N1: 데이터 8비트, 패리티 없음, 정지 비트 1개)**

평소(idle)에는 HIGH를 유지하다가, Start bit(LOW)로 전송 시작을 알린다. 데이터는 **LSB부터** 보낸다.

```
문자 'A' = 0x41 = 0b0100_0001

        idle  Start  D0 D1 D2 D3 D4 D5 D6 D7  Stop  idle
비트값    1     0     1  0  0  0  0  0  1  0    1     1
         ──┐     ┌──┐              ┌──┐     ┌─────────
           └─────┘  └──────────────┘  └─────┘
               ↑ LSB(D0)부터 전송           ↑ MSB(D7)
```

- 1바이트를 보내는 데 Start 1 + Data 8 + Stop 1 = **10비트**가 필요하다.
- 115200 bps → 1비트 = 1 / 115200 ≈ **8.68µs**, 초당 약 **11,520 바이트** 전송
- 수신 측은 Start bit의 하강 엣지를 기준으로 1비트 시간마다 값을 읽는다. baud rate가 다르면 읽는 시점이 어긋나서 **문자가 깨진다.**

### 2.6 I2C (Inter-Integrated Circuit)
- **SDA(데이터)** 와 **SCL(클럭)** **두 개의 신호선**만으로 여러 장치를 연결할 수 있어 배선이 효율적이다.
- **Master** : 클럭을 만들고 통신을 시작하는 쪽 (MCU)
- **Slave** : 고유한 **주소**를 가지고, 자기 주소가 불렸을 때만 응답하는 쪽 (IMU 등 센서)
- 활용: IMU, OLED 디스플레이, 온습도 센서 등 저속 센서

**왜 풀업 저항이 필요한가 (Open-Drain)**
- I2C 장치는 선을 **LOW로 끌어내리기만** 할 수 있고, HIGH로 올리지는 못한다 (Open-Drain 구조).
- 그래서 **풀업 저항**이 평소에 선을 HIGH로 유지하고, 장치는 필요할 때만 LOW로 끌어내린다. 여러 장치가 한 선을 공유해도 충돌(단락)이 생기지 않는다.

**I2C 통신 순서**
```
[Start] [주소 7bit][R/W] [ACK] [데이터 8bit] [ACK] ... [Stop]
   ↑    ←─ Master가 보냄 ─→  ↑   ←─ 송신측 ─→    ↑         ↑
 SCL=H일 때            Slave가 SDA를  수신측이 SDA를   SCL=H일 때
 SDA ↓                LOW로 끌어내림  LOW로 끌어내림   SDA ↑
```

1. **Start condition** : 기본 상태는 두 선 모두 HIGH. SCL이 HIGH인 동안 Master가 **SDA를 끌어내리면(↓)** 통신 시작
2. **주소 전송** : 7bit 주소 + R/W 1bit(0 = 쓰기, 1 = 읽기) = **8bit**
3. **ACK / NACK** : 해당 주소의 Slave가 **SDA를 LOW로 끌어내리면 ACK**(받았음), HIGH 그대로면 **NACK**(응답 없음 / 그만)
4. **데이터 전송** : 8bit씩 보내고 매번 ACK/NACK로 확인
5. **Stop condition** : SCL이 HIGH인 동안 **SDA가 올라가면(↑)** 통신 종료

- 데이터 비트는 SCL이 LOW일 때만 바뀌고, SCL이 HIGH일 때 읽는다. SCL이 HIGH인데 SDA가 바뀌는 경우는 Start/Stop뿐이라서 둘을 구분할 수 있다.
- 7bit 주소이므로 이론상 128개(예약 주소 제외 약 112개) 장치를 연결할 수 있다.

### 2.7 SPI (Serial Peripheral Interface)
- 신호선 4개: **SCK**(클럭), **MOSI**(Master → Slave), **MISO**(Slave → Master), **CS/SS**(장치 선택)
- 동기 방식, 전이중, 수~수십 MHz로 **가장 빠르다**.
- 주소 대신 **CS 핀을 LOW로** 만들어 통신할 장치를 고른다. 장치가 늘어날수록 CS 핀도 늘어난다.
- 클럭 극성(CPOL)과 위상(CPHA)에 따라 Mode 0~3이 있으며, Master와 Slave의 모드가 같아야 한다.
- 활용: 디스플레이, SD 카드, 고속 IMU, ADC 칩

### 2.8 CAN (Controller Area Network)
- 자동차 내부 통신을 위해 만들어진 프로토콜로, **CAN_H / CAN_L 두 선의 전압 차이(차동 신호)** 로 데이터를 보낸다. 노이즈에 매우 강하고 수십 m 거리도 가능하다.
- 주소 대신 **메시지 ID**를 사용하고, 여러 노드가 동시에 보내면 **ID가 작은(우선순위 높은) 메시지가 이기는** 중재(arbitration) 방식을 쓴다.
- 모든 노드가 Master가 될 수 있는 **멀티 마스터** 구조이다.
- 활용: 자동차 ECU, 산업용 로봇, 고성능 모터 드라이버
- ESP32에는 CAN 컨트롤러(TWAI)가 내장되어 있지만, 실제 버스에 연결하려면 **CAN 트랜시버 칩**이 따로 필요하다.

### 2.9 프로토콜 비교 정리

| 항목 | UART | I2C | SPI | CAN |
|---|---|---|---|---|
| 방식 | 비동기 | 동기 | 동기 | 비동기 (차동 신호) |
| 신호선 | TX, RX | SDA, SCL | SCK, MOSI, MISO, CS | CAN_H, CAN_L |
| 장치 구분 | 1 : 1 | 주소 (7bit) | CS 핀 | 메시지 ID |
| 속도 | ~수 Mbps | 100k / 400k / 1MHz | ~수십 MHz | ~1Mbps (CAN FD는 더 빠름) |
| 장점 | 단순함 | 선 2개로 여러 장치 | 가장 빠름 | 노이즈에 강함, 장거리 |
| 로봇 활용 | LiDAR, SBC ↔ MCU | IMU, OLED | 디스플레이, 고속 센서 | 모터 드라이버, 차량 |

### 2.10 WEMOS D1 R32 핀 배치
- **ESP32(ESP32-WROOM-32 모듈)** 를 **Arduino Uno와 같은 모양**으로 만든 보드다. Uno용 쉴드를 꽂을 수 있지만, 동작 전압은 **3.3V** 이다.
- 보드에 인쇄된 D/A 번호와 ESP32의 **실제 GPIO 번호가 다르다**. 코드에서는 **GPIO 번호**를 써야 한다.

| 보드 표기 | ESP32 GPIO | 비고 |
|---|---|---|
| D0 (RX) / D1 (TX) | GPIO3 / GPIO1 | UART0, USB 시리얼(업로드·시리얼 모니터)에 사용 중 → 일반 I/O로 쓰지 않음 |
| D2 / D3 | GPIO26 / GPIO25 | DAC 출력 가능 |
| D6 | GPIO27 | PWM |
| D9 | GPIO13 | PWM |
| D10 / D11 / D12 / D13 | GPIO5 / 23 / 19 / 18 | SPI의 CS / MOSI / MISO / SCK |
| A0 | GPIO2 | 온보드 LED와 공유 |
| A1 | GPIO4 | ADC2 (Wi-Fi 사용 시 ADC 불가) |
| A2 / A3 / A4 / A5 | GPIO35 / 34 / 36 / 39 | ADC1, **입력 전용** |
| SDA / SCL | GPIO21 / GPIO22 | 기본 I2C 핀 (IMU 연결) |

- D4, D5, D7, D8은 제조사와 보드 버전마다 연결된 GPIO가 달라서, 보드 옆에 인쇄된 **IO 번호**를 직접 확인해야 한다.
- 11/15 실습에서 가변저항에 사용한 **GPIO39** 는 이 보드의 **A5** 이다.

## 5. 실행 방법 및 재현

1. 로봇을 조립하고 IMU를 MCU의 **SDA(GPIO21) / SCL(GPIO22)** 에, LiDAR를 SBC에 연결한다.
2. MCU를 USB로 SBC(또는 PC)에 연결한다.
3. SBC에서 ROS2 환경을 불러온다.
   ```bash
   source /opt/ros/$ROS_DISTRO/setup.bash
   ```
4. 센서 데이터가 들어오는지 확인한다.
   ```bash
   ros2 topic list               # 실행 중인 토픽 목록 확인
   ros2 topic echo <IMU 토픽>     # IMU 값 출력
   ros2 topic hz <IMU 토픽>       # 데이터가 들어오는 주기 확인
   ```
   IMU 토픽 이름은 사용하는 패키지에 따라 다르므로 `ros2 topic list`로 확인한다.
5. 로봇을 평평한 곳에 정지시키고 `linear_acceleration.z` 값이 약 ±9.8인지 확인한다.

## 7. 참고 사항
- 모든 장치(SBC, MCU, 모터 드라이버, 센서)는 **Common GND** 로 연결해야 통신 신호가 안정적이다.
- I2C 센서가 인식되지 않으면 풀업 저항 유무, SDA/SCL이 바뀌어 연결되지 않았는지, 주소가 맞는지 확인한다.
- UART 데이터가 깨지면 양쪽 baud rate가 같은지, TX/RX가 교차 연결되었는지 확인한다.
- 지자기 센서는 모터와 전선에서 나오는 자기장의 영향을 받으므로, 가능하면 모터에서 멀리 설치한다.
